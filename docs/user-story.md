## حالات الاستخدام وقصص المستخدمين لمنصة حجز الأماكن والأنشطة الخارجية والترفيهية (السعودية)

هذه الوثيقة تُحوّل نطاق الـ MVP إلى متطلبات عملية قابلة للتحويل لاحقًا إلى مهام تنفيذ **Backlog**.

نستخدم مستويين من التحديد:

- **حالة الاستخدام (Use Case):** سيناريو كامل يوضح الهدف والشروط والخطوات والنتيجة المتوقعة.
- **قصة المستخدم (User Story):** احتياج مختصر للمستخدم مع شروط قبول قابلة للاختبار.

تعتمد النسخة الأولى على **فئة واحدة، ومنطقة واحدة، وحجز بفترات محددة مسبقًا لكل منها سعر وسعة**. تدير الجهاتَ وبياناتها إدارةُ المنصة، دون حسابات مستقلة للمشغلين في هذه المرحلة.

---

## 1) فئات المستخدمين

### 1. الزائر/العميل

- يبحث عن مكان أو نشاط مناسب.
- يريد معرفة التفاصيل والسعر والتوافر.
- ينشئ حسابًا لإتمام الحجز والدفع.
- يتابع حجوزاته ويلغيها وفق السياسة.

### 2. موظف التشغيل وخدمة العملاء

- يتابع الحجوزات والمدفوعات.
- يساعد العملاء ويعالج الإلغاءات ضمن صلاحياته.
- يسجل الحضور أو عدم الحضور.
- يحدث التوافر بالتنسيق مع الجهات المشغلة.

### 3. مدير المنصة

- يدير الجهات والأماكن والأنشطة والصور.
- يحدد الأسعار والفترات والسعة والسياسات.
- يدير حسابات الموظفين وصلاحياتهم.
- يتابع الإجراءات المهمة والاستردادات.

> الجهة المشغلة شريك تشغيلي في النسخة الأولى؛ تتواصل مع فريق المنصة لتحديث بياناتها وتوافرها.

---

## 2) حالات الاستخدام الأساسية

**الهدف العام:** مساعدة العميل على اكتشاف خيار مناسب وإتمام حجز مؤكد، مع إدارة دقيقة للتوافر والحجوزات.

### حالة الاستخدام 1: استعراض الصفحة الرئيسية

- **المستخدم:** زائر.
- **الهدف:** فهم ما تقدمه المنصة والوصول إلى الخيارات المتاحة.
- **الشروط:** وجود محتوى تعريفي وخيارات منشورة.
- **الخطوات:** فتح الرئيسية → قراءة التعريف المختصر → مشاهدة الخيارات → الانتقال إلى التصفح أو التفاصيل.
- **النتيجة المتوقعة:** وصول الزائر إلى مسار واضح للاستكشاف والحجز.

### حالة الاستخدام 2: التصفح والبحث والتصفية

- **المستخدم:** زائر/عميل.
- **الهدف:** الوصول إلى خيار يناسب الموقع والتاريخ وعدد الأشخاص.
- **الشروط:** وجود خيارات منشورة وفترات قابلة للحجز.
- **الخطوات:** فتح صفحة التصفح → إدخال الاسم أو اختيار الفلاتر → عرض النتائج → فتح خيار محدد.
- **النتيجة المتوقعة:** نتائج تطابق المعايير المختارة.
- **الحالة البديلة:** عند عدم وجود نتائج، تظهر رسالة واضحة وإمكانية تعديل الفلاتر.

### حالة الاستخدام 3: عرض تفاصيل المكان أو النشاط

- **المستخدم:** زائر/عميل.
- **الهدف:** فهم العرض والسعر والشروط قبل الحجز.
- **الشروط:** وجود صفحة منشورة بمعلومات مكتملة.
- **الخطوات:** فتح التفاصيل → استعراض الصور والخدمات والموقع → قراءة الشروط → اختيار الفترة وعدد الأشخاص.
- **النتيجة المتوقعة:** قدرة العميل على تحديد ملاءمة الخيار والمتابعة للحجز.

### حالة الاستخدام 4: إنشاء حساب أو تسجيل الدخول

- **المستخدم:** عميل.
- **الهدف:** الوصول إلى حسابه لإتمام الحجز ومتابعته.
- **الشروط:** توفر إنشاء الحساب وتسجيل الدخول واستعادة الوصول.
- **الخطوات:** اختيار الدخول → إنشاء حساب أو إدخال بيانات الدخول → التحقق → العودة إلى رحلة الحجز.
- **النتيجة المتوقعة:** دخول العميل مع الاحتفاظ باختياراته السابقة.
- **الحالة البديلة:** تظهر رسالة مناسبة عند فشل الدخول، مع إمكانية استعادة الوصول.

### حالة الاستخدام 5: بدء الحجز وحجز السعة مؤقتًا

- **المستخدم:** عميل مسجل.
- **الهدف:** الاحتفاظ بالسعة المطلوبة أثناء إتمام الدفع.
- **الشروط:** فترة مفتوحة وسعة كافية وعدد أشخاص مسموح.
- **الخطوات:** اختيار الفترة والعدد → إعادة التحقق من التوافر → إنشاء حجز مؤقت → عرض الملخص والمهلة والسعر الإجمالي.
- **النتيجة المتوقعة:** حجز السعة مؤقتًا دون تجاوز السعة المتاحة.
- **الحالة البديلة:** إذا تغير التوافر، يُبلغ العميل ويُطلب منه اختيار فترة أو عدد مناسب.

### حالة الاستخدام 6: الدفع وتأكيد الحجز

- **المستخدم:** عميل.
- **الهدف:** دفع قيمة الحجز والحصول على تأكيد.
- **الشروط:** حجز مؤقت ساري وموافقة على الشروط والسياسة.
- **الخطوات:** مراجعة الملخص → الموافقة → الانتقال لبوابة الدفع → التحقق من نتيجة الدفع → تأكيد الحجز.
- **النتيجة المتوقعة:** حجز مؤكد مرتبط بعملية دفع ناجحة، مع رقم حجز.
- **الحالات البديلة:**
  - فشل الدفع: لا يُؤكد الحجز، ويمكن إعادة المحاولة أثناء المهلة.
  - انتهاء المهلة: تُحرر السعة.
  - تأخر نتيجة الدفع: تظهر حالة المعالجة؛ وإذا وصل نجاح الدفع بعد انتهاء المهلة، يُعاد التحقق من السعة، وإلا يُعاد المبلغ دون تأكيد حجز متعارض.

### حالة الاستخدام 7: عرض التأكيد ومتابعة الحجوزات

- **المستخدم:** عميل.
- **الهدف:** معرفة تفاصيل الحجز والاستعداد للزيارة.
- **الشروط:** وجود حجز مرتبط بحساب العميل.
- **الخطوات:** فتح صفحة التأكيد أو «حجوزاتي» → اختيار الحجز → عرض تفاصيله وتعليمات الزيارة.
- **النتيجة المتوقعة:** ظهور رقم الحجز والموعد والعدد والمبلغ والموقع والحالة، مع إرسال تأكيد بالبريد الإلكتروني.

### حالة الاستخدام 8: إلغاء الحجز واسترداد المبلغ

- **المستخدم:** عميل.
- **الهدف:** إلغاء الحجز ومعرفة المبلغ المسترد.
- **الشروط:** حجز يسمح بالإلغاء وفق السياسة المحفوظة وقت الحجز.
- **الخطوات:** فتح الحجز → اختيار الإلغاء → عرض الرسوم والمبلغ المسترد → تأكيد الإلغاء → تحرير السعة → تنفيذ الاسترداد عند استحقاقه.
- **النتيجة المتوقعة:** تحديث حالة الحجز وإظهار حالة الاسترداد.
- **الحالة البديلة:** إذا لم يُسمح بالإلغاء، يظهر السبب ووسيلة التواصل مع الدعم.

### حالة الاستخدام 9: دخول الموظفين إلى لوحة الإدارة

- **المستخدم:** موظف تشغيل/مدير منصة.
- **الهدف:** الوصول إلى الوظائف المسموح بها.
- **الشروط:** حساب موظف فعال وصلاحيات محددة.
- **الخطوات:** فتح صفحة الدخول → إدخال البيانات → التحقق → فتح لوحة الإدارة.
- **النتيجة المتوقعة:** وصول الموظف حسب صلاحياته ومنع الوصول غير المصرح.

### حالة الاستخدام 10: إدارة الجهات والمحتوى والصور

- **المستخدم:** مدير المنصة.
- **الهدف:** نشر خيارات واضحة ومحدثة.
- **الشروط:** صلاحية إدارة المحتوى.
- **الخطوات:** إضافة جهة أو اختيارها → إضافة مكان/نشاط → إدخال التفاصيل والصور والسياسة → حفظ → نشر أو إخفاء.
- **النتيجة المتوقعة:** تحديث الموقع دون مطوّر، مع الاحتفاظ بالحجوزات السابقة عند إخفاء الخيار.

### حالة الاستخدام 11: إدارة الفترات والأسعار والسعة

- **المستخدم:** مدير المنصة/موظف مخول.
- **الهدف:** ضبط التوافر الفعلي.
- **الشروط:** وجود مكان أو نشاط وصلاحية تعديل التوافر.
- **الخطوات:** اختيار المكان → إنشاء أو تعديل فترة → تحديد السعر والسعة → تسجيل إشغال خارجي أو إغلاق الفترة → حفظ.
- **النتيجة المتوقعة:** توافر يعكس السعة القابلة للبيع.
- **الحالة البديلة:** تُرفض التعديلات التي تجعل السعة أقل من الإشغال المحجوز.

### حالة الاستخدام 12: متابعة الحجوزات والحضور

- **المستخدم:** موظف التشغيل.
- **الهدف:** تنظيم الحجوزات القادمة وخدمة العملاء.
- **الشروط:** صلاحية الاطلاع والمتابعة.
- **الخطوات:** فتح قائمة الحجوزات → البحث أو التصفية → فتح حجز → مراجعة التفاصيل → تسجيل الحضور أو عدم الحضور أو ملاحظة داخلية.
- **النتيجة المتوقعة:** سجل واضح يساعد على التشغيل والمتابعة.

### حالة الاستخدام 13: معالجة الإلغاء والاسترداد إداريًا

- **المستخدم:** موظف مخول/مدير المنصة.
- **الهدف:** معالجة إلغاء العميل أو إلغاء الجهة للحجز.
- **الشروط:** صلاحية الإلغاء والاسترداد وسبب موثق.
- **الخطوات:** فتح الحجز → تحديد سبب الإلغاء → مراجعة المبلغ المسترد → التأكيد → تنفيذ الاسترداد → إشعار العميل.
- **النتيجة المتوقعة:** إلغاء موثق واسترداد قابل للمتابعة دون تكرار العملية.

## 3) قصص المستخدمين وشروط القبول

### 3.1 قصص العميل

#### قصة المستخدم 1: فهم المنصة بسرعة

بصفتي زائرًا، أريد أن أفهم ما تقدمه المنصة وأصل إلى الخيارات بسهولة، حتى أبدأ التخطيط لزيارتي.

**شروط القبول:**

- يظهر تعريف مختصر وواضح بالمنصة.
- يوجد إجراء واضح للانتقال إلى التصفح.
- تظهر خيارات منشورة ووسيلة للتواصل مع الدعم.

#### قصة المستخدم 2: تصفح الخيارات

بصفتي زائرًا، أريد مشاهدة الأماكن أو الأنشطة في قائمة واضحة، حتى أقارن الخيارات المناسبة.

**شروط القبول:**

- كل بطاقة تعرض الاسم والصورة والموقع والسعر أو «ابتداءً من».
- يمكن فتح التفاصيل من كل بطاقة.
- لا تظهر الخيارات المخفية ضمن النتائج.

#### قصة المستخدم 3: البحث والتصفية

بصفتي عميلًا، أريد البحث بالاسم والتصفية حسب الموقع والتاريخ وعدد الأشخاص، حتى أصل إلى خيارات مناسبة.

**شروط القبول:**

- تعمل الفلاتر معًا وتنعكس على النتائج.
- عند تحديد التاريخ والعدد، تظهر الخيارات التي لديها فترة مناسبة وسعة كافية وقت البحث.
- يمكن إزالة الفلاتر.
- تظهر رسالة عند عدم وجود نتائج.

#### قصة المستخدم 4: فهم تفاصيل العرض

بصفتي عميلًا، أريد معرفة تفاصيل المكان أو النشاط، حتى أحجز بناءً على معلومات واضحة.

**شروط القبول:**

- تظهر الصور والوصف والموقع والخدمات وما يشمله الحجز.
- تظهر الفترات والمدة وحدود المشاركين.
- تظهر الأسعار والشروط وسياسة الإلغاء.
- يوجد إجراء واضح لبدء الحجز.

#### قصة المستخدم 5: الدخول واستعادة الوصول

بصفتي عميلًا، أريد إنشاء حساب والدخول إليه واستعادة الوصول عند الحاجة، حتى أحجز وأتابع حجوزاتي.

**شروط القبول:**

- يمكن إنشاء حساب ببيانات صحيحة وتسجيل الدخول.
- تظهر أخطاء مفهومة للحقول غير الصحيحة.
- تتوفر آلية لاستعادة الوصول.
- لا يفقد العميل اختيارات الحجز عند الانتقال لتسجيل الدخول.
- لا يستطيع العميل الاطلاع على حجوزات حساب آخر.

#### قصة المستخدم 6: اختيار فترة وعدد أشخاص

بصفتي عميلًا، أريد اختيار فترة وعدد أشخاص، حتى أحجز ما يناسب زيارتي.

**شروط القبول:**

- يُرفض العدد غير المسموح أو الذي يتجاوز السعة.
- يُعاد التحقق من التوافر عند بدء الحجز.
- عند التنافس على السعة الأخيرة، لا تُمنح لأكثر من حجز.
- تظهر رسالة واضحة إذا لم تعد الفترة متاحة.

#### قصة المستخدم 7: مراجعة الحجز والدفع

بصفتي عميلًا، أريد مراجعة التكلفة وإتمام الدفع، حتى أحصل على حجز مؤكد.

**شروط القبول:**

- يظهر المكان والفترة والعدد والسعر الإجمالي والرسوم قبل الدفع.
- تظهر مهلة الحجز المؤقت.
- تُطلب الموافقة على الشروط وسياسة الإلغاء.
- لا يُؤكد الحجز بناءً على عودة العميل من بوابة الدفع فقط؛ يجب التحقق من نجاح العملية.
- لا ينتج عن تكرار إشعار الدفع حجز أو خصم إضافي.
- تُحفظ تفاصيل السعر والسياسة المعتمدة وقت الحجز.

#### قصة المستخدم 8: التعامل مع تعثر الدفع

بصفتي عميلًا، أريد معرفة نتيجة الدفع وما يمكنني فعله عند التعثر، حتى لا أبقى غير متأكد من حالة حجزي.

**شروط القبول:**

- تظهر حالة واضحة: قيد المعالجة أو ناجح أو فاشل.
- يمكن إعادة المحاولة بعد الفشل إذا بقيت المهلة سارية.
- تُحرر السعة عند انتهاء المهلة.
- عند نجاح دفع متأخر، يُؤكد الحجز فقط إذا أمكن تخصيص السعة؛ وإلا يُعاد المبلغ وتظهر الحالة للعميل.

#### قصة المستخدم 9: استلام التأكيد ومتابعة الحجز

بصفتي عميلًا، أريد تأكيدًا واضحًا والوصول إلى تفاصيل الحجز، حتى أستعد للزيارة.

**شروط القبول:**

- يظهر رقم الحجز والموعد والعدد والمبلغ والموقع وتعليمات الزيارة.
- يظهر الحجز في حساب العميل.
- يُرسل التأكيد بالبريد الإلكتروني.
- فشل إرسال البريد لا يلغي الحجز المؤكد؛ يبقى التأكيد متاحًا في الحساب.

#### قصة المستخدم 10: إلغاء الحجز

بصفتي عميلًا، أريد معرفة أثر الإلغاء قبل تأكيده، حتى أتخذ قرارًا واضحًا.

**شروط القبول:**

- يُحدد السماح بالإلغاء وفق سياسة الحجز.
- تظهر رسوم الإلغاء والمبلغ المسترد قبل التأكيد.
- بعد التأكيد، تتغير حالة الحجز وتُحرر السعة.
- تظهر حالة الاسترداد منفصلة عن حالة الحجز.
- تكرار طلب الإلغاء لا ينتج عنه استرداد إضافي.

### 3.2 قصص الإدارة والتشغيل

#### قصة المستخدم 11: الدخول بصلاحيات محددة

بصفتي موظفًا، أريد الدخول إلى لوحة الإدارة حسب دوري، حتى أؤدي عملي ضمن صلاحياتي.

**شروط القبول:**

- لا يمكن دخول لوحة الإدارة دون حساب مخول.
- تُرفض الإجراءات غير المسموح بها حتى عند محاولة الوصول المباشر.
- لا يستطيع الحساب المعطل تسجيل الدخول.

#### قصة المستخدم 12: إدارة الجهات والأماكن أو الأنشطة

بصفتي مدير المنصة، أريد إضافة الجهات وخياراتها وتحديثها، حتى تظهر معلومات صحيحة للعملاء.

**شروط القبول:**

- يرتبط كل مكان أو نشاط بجهة مشغلة.
- يمكن حفظ المحتوى وتعديله ونشره وإخفاؤه.
- لا يُنشر الخيار دون استكمال معلومات الحجز الأساسية.
- إخفاء الخيار يمنع الحجوزات الجديدة ويحافظ على الحجوزات السابقة.

#### قصة المستخدم 13: إدارة الصور

بصفتي مدير المنصة، أريد رفع صور متعددة وترتيبها، حتى يرى العميل العرض بوضوح.

**شروط القبول:**

- يمكن رفع صور وفق أنواع وأحجام مسموحة.
- يمكن تحديد صورة رئيسية وترتيب الصور.
- تظهر الصورة الرئيسية في القائمة وبقية الصور في التفاصيل.

#### قصة المستخدم 14: إدارة الفترات والأسعار والسعة

بصفتي موظفًا مخولًا، أريد ضبط الفترات والأسعار والسعة، حتى يعكس الموقع التوافر الفعلي.

**شروط القبول:**

- يمكن إنشاء فترة بموعد وسعر وسعة صالحين.
- يمكن إغلاق الفترة أمام الحجوزات الجديدة.
- لا يمكن خفض السعة إلى أقل من الإشغال القائم، بما يشمل الحجوزات المؤقتة السارية.
- تغيير السعر لا يغير قيمة الحجوزات القائمة.
- إغلاق الفترة لا يلغي الحجوزات المؤكدة تلقائيًا.

#### قصة المستخدم 15: تسجيل الحجوزات الخارجية

بصفتي موظف تشغيل، أريد تسجيل الإشغال القادم من خارج المنصة، حتى لا تُباع السعة نفسها مرتين.

**شروط القبول:**

- يمكن تحديد الفترة والعدد ومرجع أو ملاحظة للإشغال الخارجي.
- يُخصم العدد من السعة المتاحة.
- يُرفض الإدخال إذا تجاوز السعة المتبقية.
- لا يُسجل الإشغال الخارجي كعملية دفع إلكترونية عبر المنصة.

#### قصة المستخدم 16: متابعة الحجوزات والحضور

بصفتي موظف تشغيل، أريد البحث في الحجوزات ومتابعة الحضور، حتى أنظم الزيارات وأساعد العملاء.

**شروط القبول:**

- يمكن البحث برقم الحجز أو بيانات العميل.
- يمكن التصفية حسب التاريخ والمكان وحالة الحجز.
- تظهر تفاصيل الحجز وحالة الدفع.
- يمكن تسجيل الحضور أو عدم الحضور للحجز المؤكد.
- يمكن إضافة ملاحظة داخلية لا تظهر للعميل.

#### قصة المستخدم 17: الإلغاء والاسترداد الإداري

بصفتي موظفًا مخولًا، أريد إلغاء الحجز وتنفيذ الاسترداد المناسب، حتى أعالج الحالات التشغيلية بوضوح.

**شروط القبول:**

- يتطلب الإلغاء سببًا موثقًا.
- يظهر المبلغ المسترد قبل التنفيذ.
- تُميز حالة إلغاء العميل عن إلغاء الجهة.
- عند إلغاء الجهة للخدمة، يُعاد كامل المبلغ المدفوع للحجز.
- تُتابع نتيجة الاسترداد الفعلية من بوابة الدفع.
- يُبلغ العميل بالإلغاء، ولا يتكرر الاسترداد للطلب نفسه.

#### قصة المستخدم 18: إدارة الصلاحيات وسجل الإجراءات

بصفتي مدير المنصة، أريد إدارة صلاحيات الموظفين ومراجعة الإجراءات المهمة، حتى أتابع مسؤولية التغييرات.

**شروط القبول:**

- يمكن إنشاء حساب موظف وتحديد صلاحياته وتعطيله.
- تُسجل تغييرات الأسعار والسعة والإلغاءات والاستردادات والصلاحيات.
- يتضمن السجل الموظف والإجراء والتوقيت والحجز أو العنصر المتأثر.
- لا يستطيع الموظف تعديل سجل الإجراءات من لوحة الإدارة.

---

## 4) استخدام الوثيقة

- تتحول قصص المستخدمين إلى مهام تنفيذ في الـ **Backlog**.
- تُستخدم شروط القبول للتحقق من اكتمال كل قصة.
- تُختبر الحالات البديلة، خصوصًا تعارض الحجوزات وتعثر الدفع والاسترداد.
- أي قصة جديدة تُراجع أولًا مقابل وثيقة نطاق الـ MVP.
- قبل التنفيذ، تُثبت الفئة والمنطقة وطريقة الدخول وبوابة الدفع والمهلة وسياسة الإلغاء.
